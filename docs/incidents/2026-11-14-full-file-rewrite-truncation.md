## 2. 触发的命令（逐字，事故版本）

```powershell
$f='\\<host>\Share\<kb>\output\<学期>\<课程>\_审计\<台账名>-20261114.md'
$lines=Get-Content $f
# 想定位「备用」小节的起始行，再保留它之前的内容 + 追加新小节
$idx=($lines | Select-String -Pattern '^# 备用｜同步电机' | Select-Object -First 1).LineNumber
"header at line $idx"; $lines[$idx-1]
$keep=$lines[0..($idx-2)]
$new=@'
# 备用｜同步电机与永磁同步（机动，不占课时）
…（本意是替换这一小节的新内容）
'@
Set-Content -LiteralPath $f -Value ($keep + $new) -Encoding UTF8   # ← 就地覆盖
```

实际输出是 `header at line `（空值），随后打印的是**倒数第二行**——这是第一个警报，但它被当成"打印小瑕疵"忽略了。文件随即被覆盖。

半小时后又用同样的思路"修补"了另一处，但那一次改用了临时文件 + 校验再覆盖（见 §5 的安全写法），没有造成第二次损失。

## 3. 根因（三处叠加，每一处单独都不致命）

1. **锚点没命中，取到 `$null`，没有断言。**
   `Select-String -Pattern '^# 备用｜同步电机'` 对中文全角「｜」与 `Get-Content` 的默认解码不匹配（同一控制台的中文输出本身就是乱码），匹配数为 0，`.LineNumber` 为 `$null`。
2. **PowerShell 的区间在端点为 `$null` 时不会报错，而是"从尾部倒数"。**
   `$idx - 2` → `-2`，于是 `$lines[0..-2]` 被解释为 `0, -1, -2` 三个元素 = 「首行 + 末行 + 倒数第二行」。
   这就是 605 行变成 3 行的机制——**一个不存在的下标，被静默翻译成三个真实下标**。
3. **`Set-Content` 就地覆盖既有文件，没有备份、没有体积校验。**
   写之前既没生成 `.bak`，写之后也没比对行数/字节数；覆盖完成即不可逆。

## 4. 为什么现有守卫没拦住（核心问题）

`lib/guard.js` 的匹配面是**删除动词**：

- `PS_DELETE_VERBS`（`remove-item`/`ri`）、`PS_DELETE_ALIASES`（`del`/`erase`/`rd`/`rmdir`/`rm`）、`POSIX_DELETE_VERBS`（`rm`/`unlink`/`rmdir`/`shred`/`srm`）；
- 以及绕过动词的旁路：`.NET` 的 `File.Delete`／`Unlink`、`fs.rm*`/`unlink*`、`xargs`、`cmd /c del`、`find -delete`、`| Remove-Item`、`-Recurse *` 等。

本次命令里**一个删除动词都没有**：`Set-Content` 是写、`Copy-Item` 是复制。已有的一条"写遮蔽"规则只覆盖

```
Out-File|Set-Content|Add-Content|Tee-Object … .(ps1|sh|bash|zsh|bat|cmd|py|js|mjs|ts)
```

即"覆盖脚本文件 → 后续被执行"这一种后果，**不覆盖数据文档**（`.md`/`.json`/`.csv`/`.yaml`）。

于是留下一个完整敞开的缺口：

> **把既有文件的内容换掉（缩短到接近零），等于删除它的内容；但守卫只看"谁调用了删除"，不看"谁把文件写没了"。**

## 5. 建议拦截规则（按实现代价从低到高）

### R1 · 覆盖既有文件 = 删除该文件（语义等价）

`Set-Content` / `Out-File` / `Copy-Item -Force` / `Move-Item` / `>` 重定向 / `Tee-Object`，当**目标是已存在的文件**时，视同一次删除：

- 先把旧文件送回收站（或强制生成 `<name>.bak-<ts>`），再允许写入；
- 无法证明"只是新增"时，默认按删除处理（与既有设计一致：能重写就重写，重写不了再拒）。

代价：`Add-Content`（追加）不应误伤——它是唯一"不替换内容"的写命令，可放行。

### R2 · 体积熔断（事后判据，最难绕过）

对既有文本文件的就地重写，落盘后比对：`新字节数 / 原字节数 < 0.5` → 判为**截断**，拒绝并回滚。
需要显式开关（如 `-AllowShrink`）才放行"确实要删内容"的正当场景。

这条能覆盖所有 R1 认不出的写法（含脚本里间接调用、变量拼出来的目标路径）。

### R3 · 区间端点必须先断言（静态 lint）

任何用于切片的端点来自变量时，若变量可能为 `$null` 就直接判红：

- `$a..$b`、`$arr[$i..$j]`、`.Substring()`、`Select-Object -Skip/-First/-Last`；
- 典型坏味道：`$idx = (… | Select-Object -First 1).LineNumber` → 随后 `$lines[0..($idx-2)]`。
- 修法只需一行：`if ($null -eq $idx) { throw "anchor not found" }`。

### R4 · 锚点未命中即失败（代码模板）

把"取锚点行号"写成必须自校验的模板，比事后拦截更快见效：

```powershell
$idx = ($lines | Select-String -Pattern '…' -Encoding utf8 | Select-Object -First 1).LineNumber
if (-not $idx) { throw "anchor not found: <pattern>" }   # ← 缺了这行，就是本次事故
```

## 6. 安全写法（事故后实际采用，可作正面样例）

```powershell
# 改既有文件：先备份 → 写临时文件 → 校验 → 才替换
$f = '…\台账.md'
Copy-Item -LiteralPath $f -Destination "$f.bak-$(Get-Date -f yyyyMMdd-HHmmss)"   # ① 永不就地覆盖
$lines = Get-Content -LiteralPath $f -Encoding utf8                              # ② 指定编码
$keep  = $lines[0..178]
Set-Content -LiteralPath "$env:TEMP\fix.md" -Value $keep -Encoding utf8          # ③ 先写临时文件
$chk = Get-Content -LiteralPath "$env:TEMP\fix.md"
if ($chk.Count -ne 179) { throw "line count mismatch" }                          # ④ 校验再替换
Copy-Item -LiteralPath "$env:TEMP\fix.md" -Destination $f -Force
```

## 7. 恢复情况

- **已重建**：现行五课（第 20 次 v11、第 21／22／23／24 次 v4）的逐页出处表 + 备用课一节——内容取自截断前在上下文里完整读过的原文。
- **已丢失**：被取代的历史节（v9／v3／第 26 次复习稿的逐页支撑）。无副本、无版本控制、无快照，按作废处理。
- 五份 draft 与页面内容**未受影响**（事故只发生在台账这一个文件上）。

## 8. 教训

1. **永不就地覆盖**：先备份再写；"改一处"不能用"整档重写"实现。
2. **整档重写只用于新建**；改既有文件用定点替换。
3. **范围端点先断言**：一个 `$null` 下标会被 PowerShell 静默翻译成一个合法但错误的三元素区间。
4. **中文锚点必须显式 `-Encoding utf8`**，找不到就抛错，不许继续算。
5. **看见异常的中间输出要停**（`header at line ` 是空值——那一刻就该停）。
6. 从守卫的角度：**"写没了"和"删掉了"是同一件事**，只看动词是看不住的。

## 9. 处置（2026-11-15 接手维护时补记）

结论先行：**R3/R4 成立并已实现；R1/R2 不成立，不实现，理由见下。** 实现落在
`lib/rewrite-guard.js`（纯函数，无 I/O），由 `classifyCommand` 在"擦除/脚本"规则之后、
"重定向到 `file_trash`"之前调用；新配置键 `blockTruncatingWrites`（默认 `true`）。

### 9.1 先把机制核实了

在本机 pwsh 7 上复现（10 元素数组）：

```powershell
$idx = $null
$lines[0..($idx - 2)]   # → L1,L10,L9   （3 个元素）
(0..-2)                 # → 0,-1,-2
$null - 2               # → -2
```

即记录 §3 第 2 条成立：不存在的下标被静默翻译成三个真实下标，"首行 + 末两行"。
**一处需要更正**：§2 说随后打印的是"倒数第二行"，而 `$lines[$idx-1]` 在 `$idx` 为 `$null`
时是 `$lines[-1]`，即**最后一行**（`$null - 1 = -1`）。若 `$idx` 实为 `0`，`0..-2` 同样是
`0,-1,-2`、`$lines[-1]` 同样是末行。两种可能给出同一个三元素区间，所以这条出入不影响
任何规则——但记录里"打印的是倒数第二行"这句话本身对不上机制。

### 9.2 R1（覆盖既有文件 = 删除）否决，三条理由

**① 它要用的补救手段，恰好在出事的那个位置上不存在。** 记录 §1 写明目标在 UNC 共享上；
而本插件的桥接脚本会主动拒绝 UNC（`scripts/recycle-bin.ps1` 的 `Test-RecyclableVolume`
：`SHFileOperationW` 在 UNC 上是**擦除**并返回成功）。所以"先把旧文件送回收站，再允许写入"
在本次事故的文件上一步都走不通。R1 的处方是空的。

**② 它是同一种结构性缺陷换了一套词汇。** 现有守卫失手的原因不是"动词表不够长"，而是
**动词表这个方法本身**：总会有下一个写法不在表里。R1 列的
`Set-Content`/`Out-File`/`Copy-Item -Force`/`>` 之外还有 `Export-Csv`、
`[IO.File]::WriteAllText`、`Invoke-WebRequest -OutFile`、`tee`、`dd of=`、`cp`、`truncate`、
`sed -i`、编译器覆盖自己的产物……而一份看起来完整、实际不完整的清单，比明说不覆盖更糟。

**③ 它的语义和本插件自己的政策相反。** 若"覆盖 = 删除"成立，`write` / `edit` 工具也是删除
（它们同样整档替换），而系统提示里写的正是"要覆盖文件就优先用 `write`/`edit`"。同一条原则
按一致性推下去会把自己的首选工具禁掉，说明原则划错了：真正要挡的不是"写"，是**"读改写同一份
唯一副本"**。

### 9.3 R2（体积熔断 + 回滚）否决，两条

**① 回滚需要覆盖前的旧内容，而拿这份副本仍然要先知道目标。** 那就回到 R1 的枚举问题。
记录里"这条能覆盖所有 R1 认不出的写法（含脚本里间接调用、变量拼出来的目标路径）"不成立：
比较"新/旧字节数"的第一步就是"知道是哪个文件"。

**② 事后钩子撤不回来。** 本插件的接缝是 `tools/pre-execute`；`tools/post-execute` 的
`PostToolDecision.block` 只能把结果换成给模型的反馈，**不回滚已落盘的截断**。要事后兜底就得
每个 shell 调用前快照整棵树（O(工作区)），而本次事故的目标在工作区之外（UNC 共享），
任何工作区快照都框不住它。

另外 0.5 这个阈值本身就与"不影响正常使用"冲突：把 605 行**有意**压缩成 30 行是正当操作，
却会被判成截断；再加一个"显式开关"，则开关永远由模型自己传——等于没有。

### 9.4 实际实现的两条规则

| kind | 命中判据 | 为什么这样切 |
|---|---|---|
| `in-place-rewrite` | 同一条命令里，同一个文件既被读又被写（`Get-Content f … \| Set-Content f`、`$c=Get-Content $f; Set-Content $f $c`、`sed -i f`、`cat f > f`、`::ReadAllText`→`::WriteAllText`），且命令里没有留下副本 | 新内容来自唯一的副本，算错就无源可还原——这是"不可逆"的真正判据，且不依赖动词枚举：只要求读/写两侧的**操作数**能对上（`$f` 会与命令内 `$f='…'` 的赋值对齐，所以一侧字面量、一侧变量也能匹配） |
| `slice-risk` | 区间/切片端点是 `<var> ± n`，该变量在同一条命令里从未断言过 `$null`，**且同一条命令还写了文件** | 这就是 R3，但加了"同一命令内还要写文件"这个收窄条件：没有写的坏切片只打印错行，不丢数据，拒它只增加往返 |

放行边界（都已写成测试）：`Add-Content` / `>>` / `-Append`（追加不是替换）、
`2> $null` / `> /dev/null`、`Clear-Content`、写**另一个**文件、端点可证非空
（`.Count` / `Measure-Object` / 字面量）、以及带 `.bak` 或"临时文件 + 校验"的写法
——即本文件 §6 的安全写法**原样通过**。

### 9.5 如何避免"改了却不生效"

| 层次 | 手段 | 落了什么 |
|---|---|---|
| 规则本身 | 事故命令逐字进测试，断言 deny + 断言消息里带着那一行断言模板 | `test/rewrite.test.mjs` |
| 规则接线 | 桩 `ctx` 驱动 `apply()`，用**钩子**而不是纯函数来验证事故命令被拒、`DELETE_GUARD_SLICE-RISK` 码正确、`reachedNext === false` | `test/registration.test.mjs` |
| 开关 | 断言 `blockTruncatingWrites: false` 真的放行——否则文档里的开关是假的 | 同上 |
| 不误伤 | 42 条日常命令（构建、git、发布、日志、配置）必须 allow，与事故用例在同一份文件 | `test/rewrite.test.mjs` |
| 缺口不隐身 | 已知不覆盖的写法（`Invoke-WebRequest -OutFile`、`git checkout --`）写进 README「不挡什么」，并在测试里**钉住现状**：一旦将来被覆盖，测试会失败，逼着同一次提交里改文档 | 同上 |
| 部署 | ⚠️ **未做**：源码已改到 2.3.0，但 profile 里装的仍是 registry 的 2.2.3，`lib/*.js` 只在进程启动时加载 | 需 pack → `remove`+`add` → 重启 `dsh web` |

**"决策类型"上的一处刻意选择**：这两条规则用 `deny`，不用 `ask`。本机 approval policy 是 `never`
（自动批准），`ask` 会在同一个 tick 里变成放行——规则看着在、其实不做任何事，正是"改失效"的
典型形态。

### 9.6 仍然未覆盖 / 未验证

- **没读过就覆盖**（`echo x > 既有文件.md`、`Invoke-WebRequest -OutFile`、`git checkout -- f`）：
  有意重写，新内容不依赖旧内容；挡它等于挡 `write`/`edit`。已列入 README「不挡什么」。
- **读改写的间接形态**：写入发生在子进程里（编译器、`npm run build`、`robocopy` 产物），
  命令文本里没有可判定的目标。
- **跨 send 的多步**：`terminal_send` 每次只看这一次的文本；先算 `$idx` 再切片写回，分两次
  发送时只剩后半段，按"来源不可证"处理（会拒，并在消息里要求同一条命令内断言）。
- **`write` 工具本身**：整档替换的截断风险同一类，但它是宿主工具、且是政策指定的首选路径，
  不在本插件范围。
- **部署后验收未做**：装载新版本后应按 AGENTS §6.5.5 的请求级办法复验一次（真实会话里跑
  事故命令 → 应被拒；再跑 `npm run build` → 应放行）。

```

→ Permanent-erase tools (…) are disabled by the recycle-bin guard. ("shred" erases …)
```

`wipeProgramInInlineBody` 只要语句里有内联体标志（`-e`/`-c`/`-Command`）就在整段里找擦除
工具名，没有区分"这段文本是 shell 程序"还是"这段文本是 JS/Python 源码里的一句说明"。于是
**维护这个插件自己的文档**被自己的规则挡住——正是"影响正常使用"的典型样子。

修法（同一版内）：`bash -c` / `pwsh -Command` 的体仍是 shell 文本，整段判定不变；其余解释器
要求名字**交给进程调用**才算（`exec` / `execFile` / `execSync` / `spawn` / `spawnSync` /
`popen` / `system` / `subprocess.*`）。`execSync('shred -u x')`、`os.system('sdelete …')`
仍然拒绝。这是同一次改动里唯一一条"降低了覆盖面"的修改，所以单独记在这里。

## 10. UNC 删除：从"一律拒绝"改成"先复制到本地再删源"（2026-11-15，用户裁定）

2.3.0 对 UNC 的处理是**拒绝**：桥接拒绝、模型拿到一句"先复制到本地 NTFS 路径"。用户裁定这不够——
留下的原件会在共享上堆成垃圾，而"删掉了"本来就是用户要的结果；回收站只是**一段时间窗口**，
过一阵清空即可。于是 2.4.0 把它做成一次调用：

1. 复制到有回收站的本地 NTFS 卷（`stagingRoot` 可配）；
2. 校验：相对路径集合、条目类型、每个文件大小；
3. 回收暂存目录（副本进回收站）；
4. **校验与回收都确认后**才删共享上的源。

**这一步与 R1 不矛盾，别混。** R1 说的是"覆盖既有文件之前，先把旧副本送回收站"——那是在**写之前动目标**，
而且对被覆盖的文件根本不需要"先回收再写"：需要的是把**内容**留一份。§9.2 的否决理由（共享上没有回收站、
动词枚举、与 `write`/`edit` 冲突）都仍然成立。这里做的是另一件事：把一个**条目的删除**换成"内容进本地回收站
＋ 条目在共享上消失"，不是给覆盖写开路。

**边界（已写进 README「网络共享」与 SECURITY.md）**：

- 保的是**内容**，不是**原路径**：`$I` 记的原位置是暂存路径，还原落点是那里，不是共享；
- 复制不保真：ACL、备用数据流、稀疏区间、属主不复制（时间戳保留）；校验用"条目集合 + 类型 + 大小"，不算哈希；
- 代价 O(体积)：需要等量本地空间，大目录可能超过工具调用时限（**未实测**）；
- 树里含重解析点（junction／符号链接）直接拒绝：复制要么把目标内容一起复制进来、要么需要权限重建链接，
  两种都不是忠实副本；
- 共享根（`\\host\share`）与只有主机名的形态拒绝——只有主机名那种还会被 `path.resolve` 读成
  `<当前盘>:\host`（实测），即一个**本地**文件，所以额外拦掉；
- exFAT/FAT32 仍是纯拒绝：同样的机制可以扩展过去，但那要先定"暂存到哪个卷"的策略，本次没做。

**验收**：`test/staging.test.mjs`（8 项，纯函数 + 注入的复制/回收替身）＋ `e2e.test.mjs` 三项，
其中一项走真实 `\\localhost\C$\…` 路径端到端删除（管理共享不可达时报告 **skipped**，不静默通过）。
